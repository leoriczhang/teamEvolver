# Single File Subsetting Policy

这是当前版本专门针对“单文件来源被整份复制”问题的限制规则。

## 1. 适用范围与核心原则
本规则用于**大簇切分**。当非 common 总内容不超过 100000 字符、且只生成一个包时，
属于小簇单包透传，允许原文完整进入唯一包，但必须在 `package_notes` 记录体量判断。

单文件来源必须被当成“可切片的来源”，而不是“必须整份保留的说明书”。

也就是说：
- 覆盖单文件来源 != 整份复制单文件来源
- 单文件来源进入样本包时，默认必须经过选择与裁剪

## 2. 默认禁止的情况
以下情况默认视为不合格：
1. 单文件来源与原文几乎完全一致
2. 只删除了极少量内容，实质仍是整份复制
3. 同一个单文件来源在多个样本包中近乎原样重复出现
4. 没有围绕当前包高层主题做裁剪

## 3. 合格的情况
一个单文件来源在样本包中合格，通常应尽量满足：
- 是原文子集
- 经过明确选择
- 与当前包高层主题相关
- 能支持包内多种关键张力维度
- 不只是为了满足覆盖而机械放入

## 4. 极少数例外
只有以下情况同时成立时，才允许接近全量保留：
1. 文件本身很短
2. 大部分内容都与当前包高层主题直接相关
3. 大部分内容都对包内多种张力维度有支撑作用
4. 已在 `package_notes` 中明确说明原因

## 5. 量化口径（会被自动校验）
- 大簇切分时，片段量达到原文 90% 及以上视为整份复制（原文 < 2000 字符的短文件豁免）
- 同一单文件来源在不同样本包中的片段互相重复度必须 < 85%，必须切原文的不同部分
- 裁剪不是"越薄越好"：每包分到的区段应完整、连续、足量，详见 `slice-depth-policy.md`
