# Package Count Decision

## 先说明两条容易犯错的事

### 1. 不要被 3 个包锚定
示例中出现 `样本包001`、`样本包002`、`样本包003`，只是为了说明命名方式。
这**绝不意味着默认应该产出 3 个包**。

### 2. 不要被低层案例维度锚定
示例中经常出现“稳定 / 冲突 / 失败 / 边界 / 伪相似”这些维度。
这**绝不意味着应该把不同样本包分别做成这五种包**。

正确理解是：
- 这些维度应尽量在每个样本包内部同时出现
- 不同样本包之间应按更高层主题区分

## 核心问题
样本包数量不是固定值。
应根据以下因素共同决定：
- 数据规模
- 高层主题数量
- 边界/冲突密度
- 覆盖增益
- 张力增益

## 应该新增一个包的条件
1. 出现新的高层主题
2. 现有包容纳后会导致主题过杂
3. 新包能显著提高总体覆盖率
4. 新包能引入新的边界/冲突/失败模式组合
5. 新包能提升高层主题分辨度，而不是只重复已有包

## 不应该新增一个包的条件
1. 新包只是重复已有包的高层主题
2. 新包带来的新增覆盖率很低
3. 新包没有新增高价值张力
4. 新包只是在细碎切分已有内容
5. 新包只是把“失败案例”或“边界案例”单独拎出去，形成低层分工包

## 简化原则
- 宁可少而扎实，不要多而碎
- 宁可一个包内部同时容纳多种关键张力，也不要把低层案例类型拆成独立包
- 只有当更高层主题确实不同，才值得新增一个包
