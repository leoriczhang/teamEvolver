# team_miner

team_miner 承载控制台的 OV Skill 挖掘与知识库挖掘。Skill 挖掘由 teamEvolver 管理真实轮次与人工 Evidence 补证，每轮调用 OpenViking Compile；知识库挖掘将来源文档编译为 Wiki，并提供文件编辑、增量编译及关系图。

## 维护入口

| 文件 | 职责 |
| --- | --- |
| `bridge.py` | Skill 挖掘路由、主服务桥接与任务监控 |
| `ov_round_orchestration.py` | 来源冻结、累积补证、独立编译器安装与幂等提交 |
| `ov_compile_mining.py` | 来源注册、任务状态、复核、归档与产物质量 |
| `compile_strategy.py` | OV Compile 能力拆分计划与共享分析、候选包契约 |
| `routes.py` | 知识库上传、编译、Wiki 编辑与发现 |
| `document_converter.py` | 上传文档转换 |
| `wiki_graph.py` | Wiki 链接索引与关系图 |
| `settings.py` | 默认轮数、运行期限与编译 Skill 配置 |
| `benchmark_format.py` | 挖掘产物与统一 Test Dataset 的格式边界 |
| `lifecycle.py` | 已完成产物提交到 Skill Candidate 生命周期 |
| `frontend/` | 当前 React 页面与测试 |
| `tests/` | OV、知识库、候选提交和 Dataset 保护测试 |

## 运行与使用

从仓库根目录启动主服务：

```bash
python -m pip install -e ".[all,dev]"
teamEvolver start --daemon
```

在 `http://127.0.0.1:52010/` 登录，配置 OpenViking 的 Endpoint、Account 和服务端凭据，再注册或上传来源目录。给来源标记 Skill 或 Knowledge 用途后，在对应页面创建任务。

Skill 挖掘支持 1–5 个真实轮次、每轮 60–7200 秒基础运行期限、人工补证、附件与来源引用、独立轮次归档、停止和删除。新任务先规划可独立执行的任务方法，再分批编译 Skill Candidate 集合；数量取决于触发场景、输入输出和独立执行、验证的边界，不按文档篇数拆分。重叠方法合并，完整流程中不能独立执行的步骤保持在同一候选内。每个规划任务最多输出 8 个候选，整轮候选数随有效方法增加。纯事实可归为事实信息；只有缺少必要 Evidence 的方法才请求补证。

默认编译 Skill 使用有界分批执行：按文件读取原始 Evidence，长文件按原始文本范围切片；每次抽取只返回一个定位索引。方法、事实及局部缺口以稳定标识保存在本地账目中；规划分批逐项记录保留、合并、事实信息或暂缓的处置，不用文件级缺口替代全部方法。每个模型任务有独立输入与输出预算，完整来源映射保留在 TE 的本地清单中。模型只选择候选，TE 确定性地展开文件任务；Test Dataset 的十二个完整案例逐个校验后由程序组装。新任务在原文联合范围及完整输入预算允许时，最多四个案例共用一个文件任务，最多四个文件共用一次现有 Compile 的 Map 和 Finalize；容量不足时缩小案例组，直到使用原单案例路径。未知事实仍保留为缺口，程序不补写业务条件。

案例批次中的每个文件使用独立输入与输出路径。组内每个案例仍有独立冻结的身份和原文范围，共享输入不能扩大单个案例的来源白名单。OV 返回完成状态仍可能只有部分文件或案例成功；TE 逐案例核对身份、来源、完整性及重复 Query，保留已校验的案例，仅对缺失或不合格案例作有界修复。失败组只拆分尚未通过的部分；单个案例的原有输出预算和三个尝试上限保持不变。

新协议的案例包接近预算时，只缩短已归档的历史 Query 和修复诊断摘录，并显式标记摘录；原始 Evidence、候选属性和案例身份保持完整。重复 Query 校验仍使用本地完整案例，详细错误保留在原有账目中。

新任务也将独立候选的正文片段和评测说明分别放进最多四个文件的 Compile 批次，沿用现有 Map 和 Finalize；每个 TE 任务仍只跟踪一个当前 Compile。本机 Skill 挖掘最多同时受理两个 Native Compile，已受理的任务必须确认终态后才释放额度。一个候选的正文片段全部校验后，控制台立即提供只读文件预览；评测、十二个案例与本轮复核完成前不能编辑或提交。失败片段单独修复，已合格文件保留。单文件预览沿用现有 2 MB 上限，大产物的生成和轮次复用不受该预览上限影响，也不会截短正文。

新建默认任务使用 `te-mining-efficient.v2`，主流程为来源处理、能力规划和产物生成。独立来源抽取包也以最多四个文件共用一次 Compile，成功索引保留，失败包单独修复。完整原文扫描结果用于定位共用约束；候选正文、案例和暂缓方法复核读取实际方法段落、必要的标题及相邻段落、已定位的共用约束原文。索引只用于选择原文位置，不代替 Evidence；无法确定约束范围或索引覆盖不完整时保守回读完整来源。完整文件范围另存审计，不再让每个候选重复编译全文。

新建默认任务同时使用 `te-direct-workflow-planning.v1`：本地保留原始方法账目及精确来源，直接比较最多二十四条相关方法并选择最多八个候选，取消中间的模型合并阶段。超出候选或输出容量时，完整窗口返回容量回执，TE 缩小窗口重新规划；容量不足不作为 Evidence 缺口，也不强行合并独立方法。规划附带的事实和局部缺口按方法原文范围及已定位的共用约束选择，并明确记录省略；正文和案例仍回读原文。依赖既有候选身份的选择按次序执行。旧任务保留冻结的八条方法合并窗口及最多四文件 Compile 协议。抽取格式错误明确指出缺失和多余字段；后续 Native 文件失败不会覆盖此前的结构修复提示。TE 保留原始输出，不通过改写不合格字段来跳过校验，也不增加格式重试上限。

新任务的 `te-source-scope.v3` 将同一来源抽取单元中的共享约束关联到实际使用该单元的方法，避免把各处局部说明汇成所有候选都需回读的全文。单独规则材料中尚无方法归属的约束仍保守保留；相关约束范围不明时回读对应完整文件，分类覆盖不完整时回读完整来源。全部原文、完整文件范围与关联校验记录保留。抽取同一窗口中同目的、同终态的情境及子步骤时，保留为一个方法的条件分支；独立方法仍分别记录。新的身份复核可选择已存在的完整流程作为合并后保留的候选，避免因子步骤较早生成而只留下狭窄元数据；上一轮已有权威身份仍优先，不改写业务字段。这些变化不增加模型阶段，也不更改 OV 接口。

新任务使用更精确的原文切片：每片序列化预算 4096 字符，每个来源抽取窗口最多三片，保持原来的输入密度，并完整保存字符偏移、摘要与原文。正文和案例继续按实际输入预算打包，不按小切片数量机械拆成更多任务。同一任务的后续轮次只复用相同切片设置与已复核结果。逐项规划会明确报告遗漏、重复或未知的方法 ID；新建任务使用 `te-selection-recovery.v2`，一次格式修复仍不合格时，只缩小该批原始窗口，处理完这个窗口后恢复正常批次大小。局部格式问题不限制其余来源的处理规模。没有任何不合格处置被自动接受，也不会补写业务事实；单个方法仍无法校验时，有限重试后如实失败。来源编译指令明确使用已提供的输入内容，不把输入文件名或格式名称当作额外附件读取；规划复用行遵守现有格式，不另建顶层复用数组。金额、期限和历史数据必须保留原材料中的示例与适用条件。

相近方法通过有界的本地索引进入同一比较窗口，由编译 Skill 判断是否属于同一完整工作流程。客户画像、场景编号、示例数值和不能独立执行的子步骤优先作为输入、分支和案例，不按这些变化逐项建立候选；目的、产出或规范边界不同的方法保持独立。程序只安排比较和校验来源，不按文本相似度强行合并。复用行附带的元数据只有与已知权威值完全一致时才去除重复字段，业务改值仍拒绝。已有任务沿用冻结流程和编译器，不在恢复时切换到新协议。

新任务的规划使用当前请求内的短编号：`m001` 表示方法，`c001` 表示已知候选，`u001` 表示声明的来源或容器。TE 在提交前冻结短编号与原始标识之间的双射、完整原始规划包及哈希；恢复时读取这一冻结映射。模型必须完整处置全部方法，未知、遗漏、重复或跨角色引用仍拒绝；程序不按相近拼写猜编号。验收后再确定性还原原始标识并执行现有来源与候选校验。此变化不增加模型阶段，也不改变 Evidence 或业务内容。

规划中的暂缓提议先按原始来源分批复核；摘要未重述规则不能作为缺证结论，执行时由用户提供的输入值也不等于缺少规则。确认相关原文仍不足时才保留暂缓原因。候选身份在批次间复用，语义相近的方法另作有界复核；合并只针对同一完整任务方法，保留全部来源、方法谱系和原有案例标识。相同来源或共用公式本身不构成合并理由；相似检索和有限复核不保证发现所有语义重复。

新任务按固定的相近候选范围复核身份，并保存候选版本之间的复核回执；没有变化的集合不重复执行第二遍，实际合并或来源变化后才再复核。名称冲突修复会累积此前的冲突约束，明确同一方法复用或不同方法独立命名，不由程序拼接业务字段。

新的原文复核将材料分成最多 768 字符的连续片段，模型只选择当前任务提供的片段标识，TE 按冻结的原文位置和哈希取回引用，不让模型重抄或重排表格。实际 JSON 大小决定每批片段数，来源全文不会因分批而截短。已冻结的文本引用请求仍按原契约校验；Unicode 引号、空白和独立列表符号的排版差异只用于唯一定位，数字、运算符、业务词变化或定位歧义仍拒绝。引用出处校验不证明方法语义完整，候选正文与案例仍需核对业务条件和例外。

来源逐文件冻结到本地，只在清单中保留路径、摘要和大小，取消原始来源总计 128 文件／16 MB 的限制。单个文本文件限 20 MB，目录限 10000 个文件；累计人工补证使用独立限额。完整修订产物保留在本地轮次归档，模型只接收当前任务相关且有界的修订上下文。新默认契约根据输入分片和产物生成工作量延长每轮基础运行期限，任务详情展示本轮实际期限；人工等待不计时，单次调用和修复次数仍有界。

来源目录通过现有 OV 文件列表接口逐目录分页遍历，不使用固定深度或树节点数截断来源。单个 Skill 正文逐段校验并原子写入，最终身份校验与归档哈希分块读取，避免把完整正文重复载入内存；正文不会因组装而截短。

默认编译 Skill 使用现有 OpenViking Compile 的 Map 和 Finalize 接口。TE 将来源抽取、方法规划、文件生成和案例生成拆成有界任务，逐阶段校验后推进；不修改 OV 代码、不依赖私有内部记录或新增运行时能力。业务规则保存在编译 Skill，大小控制、来源映射、重试和组装由 TE 负责。旧冻结请求和自定义编译 Skill 不在恢复时自动改写，知识库挖掘保持其原有 Compile 链路。

每轮共享 `analysis/evidence-map.md`、`gaps.md`、`review.json` 和 `capability-plan.json`。能力拆分计划使用 `skill-miner.plan.v1`，包含 `schema_version`、`skills` 和 `deferred`；候选条目记录 `name`、`task`、`trigger`、`inputs`、`outputs`、`boundary`、`rationale` 与 `source_refs`，暂缓条目记录 `reason` 与 `source_refs`。默认分批流程另生成 `analysis/method-dispositions.md` 及 `analysis/dispositions/page-0001.md` 等分页，逐条列明提议去向、候选名称、原因与来源；纯事实不自动成为补证问题。每个候选在 `compiled_skill/<skill-name>/` 下有独立的 `SKILL.md`、`EVALUATION.md`、`BENCHMARK.md` 和 `benchmark.json`；后者使用 `team-replay.dataset`，包含 12–24 个案例。零候选保留共享分析和逐项处置说明，不产生可提交的候选包；只有事实信息时不必虚构 Evidence 缺口。

首轮从冻结的原始来源确定并保存主要语言；中文主导的材料使用简体中文。后续轮次沿用该语言，不因旧英文产物或补证语言改变。Skill Candidate 正文、说明、案例 Query、Checklist 自然语言以及共享分析和复核问题使用该语言；字段名、ID、文件路径、来源 URI、代码、固定枚举及原文直接引用保持原样。`Checklist`、`Evidence`、`Materials` 等结构标签保持不变。

控制台没有独立的输出语言选择器。运行时将任务语言规则加入新的 Compile 请求，自定义业务编译指令原样保存，无需为语言更新而重置。已受理的请求和已完成的产物不追溯修改，也不会自动翻译或重新 Compile。

控制台按 Skill Candidate 分组浏览产物，每张卡片包含能力说明、该候选的结构校验结果和四个文件。共享分析、暂缓内容与任务级 Evidence 问题单独展示；历史轮次采用相同分组，只读查看。结构校验通过不代表业务事实正确，也不代表已经通过 True Replay。

初次产物同步时，系统从结构合格的 `benchmark.json` 确定性地规范化已生成的 `BENCHMARK.md`，使案例、Checklist 和来源一致，不添加案例或事实。候选分别校验；某个候选缺失 `SKILL.md` 或其他必需文件时独立标记为产物不完整，不能提交，但不阻止其他结构合格的候选。规范化不补齐缺失的必需文件。

上一轮候选集合仅作为修订上下文；原始来源和人工补证才是 Evidence。已有任务保留单候选的七文件契约及冻结编译器版本，不在恢复或继续时自动切换。已保存的旧单候选自定义编译 Skill 继续使用单候选契约并显示兼容性警告；重置为当前默认编译 Skill 后创建的新任务才使用多候选。

后续轮次可复用同一任务紧邻的已复核轮次结果：原文抽取要求来源字节、编译指令与语言一致；候选文件和案例还要求业务字段、完整来源范围及归档哈希一致，并重新通过产物校验。新增 Evidence 或复核意见影响的候选重新生成；无法确定影响范围时全部重新生成。复用不省略本轮复核，也不代替 True Replay。

精确来源范围按原文哈希及字符区间映射到下一轮，无法确认时回退到完整文件。复用还校验流程协议、共用约束范围和方法谱系；即使两个分支来自同一原文片段，新增分支也不能复用只覆盖旧分支的产物。案例输入按方法段落与原文约束配对并有界轮转，结构和来源校验仍不证明所有业务场景已通过真实执行。

完成后可以预览、编辑产物，选择具体 Skill Candidate，连同其专属 Test Dataset 提交到 True Replay 与 Candidate Review。每个候选保留独立的验证、评审和 Publish 结果，通过门禁后进入已有 Skill 库。挖掘不会自动 Publish。

运行状态及复核记录在本地任务目录持久化；来源、补证和远端输出使用 OpenViking。不要删除仍在执行或等待复核任务的本地目录，也不要将运行数据或凭据提交到 Git。

详细操作见 [Skill 挖掘](../docs/zh/guides/07-skill-miner.md)、[多轮补证](../docs/zh/guides/17-multi-round-skill-mining.md) 和 [API](../docs/zh/api/17-skill-mining.md)。

## 验证

```bash
python -m pytest team_miner/tests tests/test_dataset_schema.py
npm --prefix web-ui test -- --run
npm --prefix web-ui run build
node docs/scripts/check-docs-refs.mjs
```

测试使用独立临时目录和模拟 OV，不应读取或改写本机运行中的任务。修改主服务后应按根目录 AGENTS.md 的进程约定重启服务。
