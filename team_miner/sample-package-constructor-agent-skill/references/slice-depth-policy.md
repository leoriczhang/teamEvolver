# Slice Depth Policy（切片深度与去重量化指标）

本规则是对 `single-file-subsetting-policy.md` 与 `global-coverage-policy.md` 的量化补充，
专门约束"广而薄"的失败模式：包很多、每包每个文件只切一小段、不同包切同一段。

产物会被流水线中的自动校验器（`validate_sample_packages.py`）按同样口径检查，
不达标会被打回重做。

## 1. 核心取向：深度优先

- 宁可少包深切，不要多包浅切
- "覆盖所有来源" != "每包对每个来源只切一小段"
- 当"覆盖广度"与"切片深度"冲突时，优先保证深度，用更少的包解决广度

## 2. 量化指标（默认口径，可按下游上下文能力调整，需与校验器同步）

| 指标 | 默认阈值 | 不达标后果 |
|---|---|---|
| 每包非 common 实质内容量 | >= 8000 字符（簇本身更小则按簇总量折算） | 硬伤，打回 |
| 每包内容总量 | <= 200000 字符 | 硬伤，打回 |
| 跨包并集吸收率（并集片段量 / 簇原文总量） | >= 25% | 硬伤，打回 |
| 同一单文件来源跨包片段互相重复度 | < 85%（逐字节相同=直接不合格） | 硬伤，打回 |
| 单文件来源片段量 / 原文量 | 大簇切分时 < 90%（短文件豁免；总量 <= 200000 字符的单包小簇透传不适用） | 硬伤，打回 |
| 目录来源采样密度 | 见 source-coverage-policy | 警告 |
| 目录来源并集文件覆盖 | >= 80% | 警告 |

## 3. 如何同时满足"每包覆盖所有来源"与"跨包不重复"

对每个单文件来源：
1. 先把原文按章节/主题划成若干**互不重叠的区段**
2. 把不同区段分配给不同包
3. 每包分到的区段应**完整、连续、足量**（切完整章节，不是从每个区段各抄两行）

这样每个包都覆盖了该来源（满足覆盖规则），但覆盖的是不同深度区段（满足去重与吸收率）。

## 4. 常见不合格模式

- 包数很多，但每包每个文件只切 300~500 字符的"目录式摘要"
- 各包对同一文件切同一段内容，只是换措辞或换页码标注
- 用"已覆盖所有来源"当理由，回避每包证据量不足的问题
