# Source Coverage Policy

这是当前版本最重要的覆盖规则说明。

## 1. 区分两种来源

### A. 单文件来源
指原始输入目录根下的独立文件，例如：
- 术语与定义.md
- 业务流程说明.md
- 审批规范.md
- 常见案例汇编.md
- 服务标准.md

### B. 目录来源
指原始输入目录中的子目录，例如：
- 操作手册/
- 历史案例/
- 政策文件/

## 2. 对单文件来源的要求
每一个样本包都必须：
- 对每一个单文件来源至少采样一次
- 不允许某个单文件来源在某个样本包中完全缺席

## 3. 对目录来源的要求
每一个样本包都必须：
- 对每一个目录来源至少采样到一些文件
- 不允许某个目录来源在某个样本包中完全缺席

但：
- 不要求目录中的每一个文件都在每个样本包中出现
- 只要求目录这个来源类别被覆盖到

## 4. 例子

原始输入：

input/
├── 术语与定义.md
├── 业务流程说明.md
└── 历史案例/
    ├── 案例1.md
    ├── 案例2.md
    └── 案例3.md

则每个样本包都必须有：
- 术语与定义.md 的子集
- 业务流程说明.md 的子集
- 历史案例/ 中至少一些案例文件的子集

允许：
- 样本包001 选 案例1 + 案例3
- 样本包002 选 案例2
- 样本包003 选 案例1 + 案例2

不允许：
- 样本包某一次完全没有 `历史案例/`


## 5. 目录来源的采样密度要求

目录来源不要求“每个文件都进入每个包”，但要求“每个包里都要有足够密度的代表性采样”。

默认规则：

- 若目录内文件数 `N <= 4`：至少采样 `N-1` 个文件
- 若目录内文件数 `5 <= N <= 8`：至少采样 `ceil(0.5 * N)` 个文件
- 若目录内文件数 `N > 8`：至少采样 `max(4, ceil(0.35 * N))` 个文件

## 6. 全局上的目录文件覆盖要求

跨全部样本包的并集，对于每一个目录来源：
- 应尽量覆盖 80% 以上的文件
- 如果仍有大量文件未被使用，应检查：
  - 包数是否偏少
  - 每个包对目录来源的采样是否过薄
  - 是否把“目录已出现”误当成“目录已充分使用”

## 7. 禁止的偷懒方式

以下情况视为不合格：
- 目录里有很多帖子，但每个样本包都只拿 1 到 3 篇
- 目录来源名义上出现了，但并没有形成足够代表性的样本覆盖
- 大部分帖子在全部样本包中都没有被用到，且没有合理说明


## 8. 包内张力维度覆盖要求

除来源覆盖之外，每个样本包内部还应尽量同时包含：
- 稳定案例
- 冲突案例
- 失败案例
- 边界案例
- 隐含前提不同但表面相似的案例

注意：
- 这里强调的是“每个包内部尽量都要有”
- 不是要求把不同包分别固定成五种不同职责


## 9. 单文件来源的裁剪要求

单文件来源在每个样本包中都必须出现，但出现方式应是“有效裁剪后的子集”，而不是整份复制。

默认要求：
- 单文件来源必须围绕当前包高层主题裁剪
- 必须优先保留真正支撑包内关键张力维度的片段
- 若一个单文件来源在多个样本包里都出现，其保留片段通常也应因主题不同而有所区别
