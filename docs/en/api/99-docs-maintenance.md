# Docs Maintenance Guide

This page describes the docs directory conventions, writing rules and checks. Docs are maintained as Markdown under `docs/` in the repository; the console has no built-in docs reader.

## When to Update Docs

| Change | Update |
| --- | --- |
| Add, change or remove a route | Regenerate the [Endpoint Index](./00-endpoints.md) and update the matching API page |
| Change the Agent data plane (Session, Context, Skill pull) | The matching `docs/{zh,en}/api/` page, [Protocol v2](../agent-integrations/06-protocol-v2.md) and `docs/schemas/` |
| Add or change CLI commands, bootstrap fields or environment variables | [Configuration Reference](../guides/01-configuration.md), [CLI Guide](../guides/05-daemon-cli.md) |
| Change PostgreSQL tables, OpenViking paths or directory layout | [Storage and Directory Layout](../concepts/09-storage-layout.md) |
| Change terminology | `CONTEXT.md` at the repository root and the pages using the term |
| Move or rename code files | Every page referencing the old path |

## Directory Structure

```text
docs/
├── README.md            # docs index
├── zh/                  # Chinese docs
│   ├── getting-started/
│   ├── concepts/
│   ├── guides/
│   ├── agent-integrations/
│   ├── api/             # 00-endpoints.md is generated by a script
│   ├── faq/
│   └── about/
├── en/                  # English docs, same names and structure as zh/
├── design/              # design notes
├── agents/              # Coding Agent collaboration conventions
├── schemas/             # Agent protocol JSON Schemas
├── assets/              # images, served at /docs-assets/
└── scripts/check-docs-refs.mjs
```

See the [Docs Index](../../README.md) for the current maintained scope.

## File Naming

- Use numeric prefixes for ordering, such as `01-overview.md`, joined to the name with `-`.
- File names are lowercase English with words joined by `-`.
- Every page must exist under the same name in both `docs/zh/` and `docs/en/`, with the same number of `#`, `##` and `###` headings.

## Writing Rules

- State the system's current behavior directly; do not describe historical versions or removed features.
- Keep endpoints, fields, commands, environment variables and code paths consistent with the implementation, and keep identifiers in their original English.
- Use the terms defined in `CONTEXT.md`: Agent, Session, Skill, Skill Candidate, True Replay, Replay Adapter, team Memory, tenant key, service Root Key and so on.
- Tag code blocks with a language (`bash`, `json`, `python`, `yaml`, `text`).
- No emoji and no HTML tags.
- Anonymize screenshots first, save them under `docs/assets/`, and reference them as `/docs-assets/<file>`.

## Code References

Write repository-relative paths in backticks, optionally with a symbol name:

- `teamEvolver/app.py:create_app`
- `team_skills/api/candidates.py:create_router`
- `session_ingestion/push/protocol.py`

References can point to `.py`, `.ts`, `.tsx`, `.sh`, `.sql` and `.mjs` files under `teamEvolver`, `team_memory`, `team_skills`, `team_replay`, `team_miner`, `session_ingestion`, `web-ui`, `scripts`, `cicd_scripts` and `tests`. Relative links to repository files or directories also work, for example `[app.py](../../../teamEvolver/app.py)`.

## Endpoint Index

The [Endpoint Index](./00-endpoints.md) is generated by `scripts/docs_endpoint_index.py` from the routes actually composed by `teamEvolver/app.py:create_app`; `MODULES` in the script maps each source file to its detail page. Regenerate after changing routes:

```bash
.venv/bin/python scripts/docs_endpoint_index.py zh > docs/zh/api/00-endpoints.md
.venv/bin/python scripts/docs_endpoint_index.py en > docs/en/api/00-endpoints.md
```

Register new API modules in `MODULES` first, otherwise the script fails.

## Checks

```bash
node docs/scripts/check-docs-refs.mjs --strict
.venv/bin/python -m pytest tests/contracts/test_docs.py
```

`check-docs-refs.mjs` scans `docs/zh`, `docs/en`, `docs/design`, `docs/README.md` and `docs/coding-agent*.md` and checks:

1. Files referenced in backticks exist and symbols have a `def`, `class` or assignment in the file (a missing symbol is a warning).
2. `file:///` references, Markdown page links, relative links to repository files or directories, and images exist.
3. zh and en pages correspond one to one (a missing page is a warning).
4. `docs/schemas/*.schema.json` files referenced by docs exist, and every schema in `docs/schemas/` is referenced by at least one page (unreferenced is a warning).

`--strict` treats warnings as failures too.

`tests/contracts/test_docs.py` checks:

1. The endpoint index matches the routes of `create_app`.
2. Every TeamEvolver route written in backticks in docs, `README.md`, `README.en.md` and `AGENTS.md` exists (upstream paths such as `/api/v1/` and `/api/public/` excepted).
3. Every `teamEvolver <command>` in docs is a registered CLI command.
4. Every `TEAMEVOLVER_*` environment variable in docs is read by code.
5. zh and en pages have the same number of headings.

## Pre-Commit Checklist

- [ ] Both check commands pass
- [ ] New pages exist in both languages with the same heading structure
- [ ] The endpoint index was regenerated if routes changed
- [ ] Example fields match the parameter tables
- [ ] Screenshots are anonymized
