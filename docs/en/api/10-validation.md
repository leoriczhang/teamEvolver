# Validation and Candidate API

## 1. API Implementation Overview

The Validation and Candidate API is used to manage candidate Skills generated by the evolution process. When teamEvolver mines Skill optimization suggestions from session data, it creates Candidates and validates them through True Replay. Administrators can use these interfaces to review pending candidates, approve publication, reject them, and view baseline/candidate Replay comparison results.

Code implementation: `teamEvolver/proxy/routes.py` (endpoints like `api_validation_candidates`)
Validation storage: `teamEvolver/validation/store.py` (`ValidationStore`)
Validation Worker: `teamEvolver/validation/worker.py` (`ValidationWorker`)
True Replay engine: `teamEvolver/true_replay.py`
Progressive Replay decision: `teamEvolver/progressive_replay.py`

## 2. Interface and Parameter Specification

All `/api/validation/*` endpoints require a console login. Release decisions and Candidate deletion require the administrator role.

---

### GET /api/validation/candidates

List Candidates.

**Authentication:** Console Cookie. The compatibility endpoint `GET /validation/candidates` is provided by the embedded evolution service and does not require a console Cookie; expose it only on a trusted network.

**Query Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `scope` | string | No | Filter scope: `open` (pending review, default), `processed`/`history`/`closed`/`decided` (processed), `all` (all) |
| `limit` | integer | No | Items per page, 1-200, default 20 |
| `offset` | integer | No | Pagination offset, default 0 |
| `refresh` | boolean | No | Whether to force refresh cache, default false |
| `compact` | boolean | No | Whether to return compact format (without large fields like diff), default false |

**Response Fields:**

| Field | Type | Description |
|-------|------|-------------|
| `candidates` | array | Candidate list |
| `total` | integer | Total count |
| `limit` | integer | Current page size |
| `offset` | integer | Current offset |
| `has_more` | boolean | Whether more data exists |

**Candidate Object Fields:**

| Field | Type | Description |
|-------|------|-------------|
| `job_id` | string | Job ID |
| `skill_name` | string | Skill name |
| `proposed_action` | string | Proposed action (update/create/delete) |
| `review_status` | string | Review status: `open`, `published`, `rejected` |
| `rationale` | string | Optimization rationale |
| `test_dataset_count` | integer | Test dataset count |
| `recommended_publish` | boolean | Whether publication is recommended (based on Replay evaluation) |
| `replay_verdict` | string | Replay verdict: `accept`, `reject`, `inconclusive` |
| `evaluation` | object | Evaluation result (including replay details) |
| `decision` | object | Review decision (when processed) |
| `decision.status` | string | `published` or `rejected` |
| `decision.accepted` | boolean | Whether approved |
| `decision.reason` | string | Decision reason |
| `decision.version` | integer | Version number after publication (when approved) |
| `candidate_skill_md` | string | Candidate SKILL.md content (when compact=false) |
| `current_skill_md` | string | Current SKILL.md content (when compact=false) |
| `skill_diff` | string | Unified diff (when compact=false) |

**Caching:** Candidate list cached for 15 seconds.

Code entry point: `teamEvolver/proxy/routes.py:4040` (`api_validation_candidates`)

### GET /api/validation/candidates/{job_id}/detail

**Path Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|

Code entry point: `teamEvolver/proxy/routes.py:4077` (`api_validation_candidate_detail`)

### POST /api/validation/candidates/{job_id}/evaluate

Execute True Replay evaluation on a candidate, generating baseline/candidate comparison results.

**Authentication:** Console Cookie (admin)

**Path Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `job_id` | string | Yes | Job ID |

**Query Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `refresh` | boolean | No | Whether to force re-evaluation (ignore cache), default false |

**Response Fields:** Evaluation results, including:

| Field | Type | Description |
|-------|------|-------------|
| `status` | string | `evaluated` |
| `skill_name` | string | Skill name |
| `recommended_publish` | boolean | Whether publication is recommended |
| `replay.verdict` | string | Verdict result |
| `replay.no_regression` | boolean | Whether no regression |
| `replay.cases` | array | Baseline/candidate comparison for each test case |
| `replay.cases[].baseline` | object | Baseline branch result |
| `replay.cases[].candidate` | object | Candidate branch result |
| `replay.efficiency` | object | Efficiency comparison (dimensions include turns/tool_calls/tokens with baseline/candidate/delta/winner) |
| `replay.checklist` | object | Checklist comparison |
| `candidate_skill_md` | string | Candidate content |
| `current_skill_md` | string | Current content |
| `skill_diff` | string | diff |

**Replay Execution Timeout:** Controlled by environment variable `TEAMEVOLVER_TRUE_REPLAY_TIMEOUT_S` (default 90 seconds); maximum interaction turns controlled by `TEAMEVOLVER_TRUE_REPLAY_MAX_INTERACTIONS` (default 4).

Code entry point: `teamEvolver/proxy/routes.py:4082` (`api_validation_candidate_evaluate`)

### POST /api/validation/candidates/{job_id}/validate

Review a candidate and decide whether to publish. When `mode=force`, ignores automatic evaluation results and forces publication.

**Authentication:** Console Cookie (admin required)

**Path Parameters:**

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `job_id` | string | Yes | Job ID |

**Request Body:**

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `mode` | string | No | Review mode: `auto` (default, decide based on evaluation results), `force` (force publish, ignore evaluation) |

**Response Fields (Successful Publication):**

| Field | Type | Description |
|-------|------|-------------|
| `status` | string | `published` |
| `accepted` | boolean | `true` |
| `job_id` | string | Job ID |
| `skill_name` | string | Skill name |
| `created` | boolean | Whether newly created (Skill didn't exist before) |
| `version` | integer | New version number after publication |
| `loaded_skills` | integer | Number of Skills reloaded |
| `cloud` | object | Cloud sync result |
| `evaluation` | object | Evaluation result |

**Response Fields (Rejection):**

| Field | Type | Description |
|-------|------|-------------|
| `status` | string | `rejected` |
| `accepted` | boolean | `false` |
| `reason` | string | Rejection reason |

Code entry point: `teamEvolver/proxy/routes.py:4096` (`api_validation_candidate_validate`)

## 3. Usage Examples

### List Pending Review Candidates

```bash
curl -b "teamEvolver_console_session=<token>" \
  "http://localhost:52010/api/validation/candidates?scope=open&limit=10"
```

Example response:

```json
{
  "candidates": [
    {
      "job_id": "job-20240115-001",
      "skill_name": "database-debugging",
      "proposed_action": "update",
      "review_status": "open",
      "rationale": "Added connection pool configuration guide, reducing tool call count",
      "recommended_publish": true,
      "replay_verdict": "accept",
      "test_dataset_count": 2,
      "evaluation": {
        "replay": {
          "verdict": "accept",
          "no_regression": true,
          "efficiency": {
            "dimensions": {
              "interaction_turns": {"baseline": 3, "candidate": 2, "delta": 1, "winner": "candidate"},
              "tool_call_count": {"baseline": 5, "candidate": 3, "delta": 2, "winner": "candidate"},
              "total_tokens": {"baseline": 5200, "candidate": 4100, "delta": 1100, "winner": "candidate"}
            }
          }
        }
      }
    }
  ],
  "total": 1,
  "limit": 10,
  "offset": 0,
  "has_more": false
}
```

### View Candidate Details and Replay Results

```bash
curl -b "teamEvolver_console_session=<token>" \
  "http://localhost:52010/api/validation/candidates/job-20240115-001/detail"
```

### Execute Replay Evaluation

```bash
curl -X POST -b "teamEvolver_console_session=<token>" \
  "http://localhost:52010/api/validation/candidates/job-20240115-001/evaluate"
```

### Approve Publication

```bash
curl -X POST -b "teamEvolver_console_session=<token>" \
  -H "Content-Type: application/json" \
  "http://localhost:52010/api/validation/candidates/job-20240115-001/validate" \
  -d '{"mode": "auto"}'
```

Example response:

```json
{
  "status": "published",
  "accepted": true,
  "job_id": "job-20240115-001",
  "skill_name": "database-debugging",
  "created": false,
  "version": 4,
  "loaded_skills": 6,
  "cloud": {
    "synced": true,
    "action": "push",
    "event_id": "skill_evt_a1b2c3d4..."
  },
  "evaluation": {...}
}
```

### Force Publication (Ignore Evaluation)

```bash
curl -X POST -b "teamEvolver_console_session=<token>" \
  -H "Content-Type: application/json" \
  "http://localhost:52010/api/validation/candidates/job-20240115-001/validate" \
  -d '{"mode": "force"}'
```

### Reject Candidate

```bash
curl -X DELETE -b "teamEvolver_console_session=<token>" \
  "http://localhost:52010/api/validation/candidates/job-20240115-001"
```

## 4. Response Contract and Error Handling

### Error Codes

| HTTP Status | Error Message | Cause |
|------------|--------------|-------|
| 401 | `login required` | Not logged in |
| 403 | `only admin users can perform this operation` | Non-admin performing write operations |
| 404 | `candidate not found` | job_id does not exist |
| 400 | `candidate missing skill payload` | Candidate missing Skill content (cannot publish) |

### Checklist Gate Policy

Pass conditions for candidate Skills:

1. **All Checklist Items Pass:** All checklist items must pass; Checklist completion is a gate condition, not a weighted score.
2. **No Efficiency Regression:** The candidate branch is no worse than baseline across interaction_turns, tool_call_count, and total_tokens dimensions (`no_regression: true`).
3. **Efficiency Comparison Order:** turns first, then tool_calls, finally tokens.

When the above conditions are not met, `recommended_publish` is false and `mode=auto` will automatically reject. `mode=force` can bypass automatic checks to force publication.

Code: `teamEvolver/progressive_replay.py` (`progressive_replay_decision`)

### Version Management for Published Candidates

- After approval for publication, Skill version number is automatically incremented;
- New version content is written to local skills directory and synced to cloud;
- Publication triggers Skill Sync webhook, notifying all registered Agents to update;
- Skill Manager automatically reloads; new Skills are immediately available in the next session.
