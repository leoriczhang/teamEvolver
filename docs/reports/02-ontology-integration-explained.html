01 / 工程架构：统一运营，复用编译

源码边界清楚：TE 的本体编排集中在 team_ontology；OV 的认证、目录、内容、ACL、Compile 和任务接口保持原有职责。正式发布仍走已有企业扩展，不让普通 Agent 获得发布能力。

02 / 从目录到正式版本的六步

默认最多 1,000 个正文文件、20 层目录、10,000 个条目、20 MiB 正文，单文件 2 MiB。超限报错；单文件失败记录缺口，身份失效或全局服务故障中止。部分覆盖需要审批人显式确认，不因目录删文件自动删正式事实。

目录逐项冻结，不能代表跨来源同一时刻的快照。每次读取、复用与发布继续检查当前权限。输入和输出目录在写入前设置 restricted ACL，并验证其他用户不能读原文或检索草稿。

03 / 签收争议：先说明证据能证明什么

一个 Wiki 文件夹包含《运单事件》《签收凭证规范》《异常处理规则》。首次 Compile 同时提出 Shipment、签收状态及其限定条件，并抽取有精确引文的草稿。审核人确认 Schema 后，TE 直接生成候选，无需让模型重读所有文章。

保持定义或仅改名

把 Shipment 映射为“运单”，确认类型映射。TE 重写标识、校验谓词和证据，以确定性程序转换草稿；该路径不新增 Compile 调用。

新增业务语义

新增“签收人是否有代理授权”。已知依赖时通过接口指定受影响来源，否则全量重编译。新轮次使用新目录，最多两次自动修复或补编译。

    04 / 核心模块如何工作

    模块实现方式关键边界
    来源集合分页广度遍历、URI 去重、稳定来源 ID、逐文件冻结回执与 checkpoint排除隐藏项及不支持附件，不跟随目录外引用
    持久化编排PG jobs/outbox、租约、执行代次、提交前保存唯一目标与请求摘要响应丢失先查原生任务；无法唯一确认则停在受理待确认
    专用 Skill每个原文批次同时输出事实草稿与类型摘要；合并复用结构化草稿固定版本，显式安装；模型遵循情况需真实验证
    确定性后处理核验契约、覆盖区间、精确引文、Unicode 偏移、类型、限定条件；同身份实体合并歧义引文拒绝；保留相反断言；覆盖声明不能证明模型没有遗漏
    Schema 与缓存摘要绑定确认，改名映射；输入、Skill、契约、模型配置版本匹配时复用成功草稿默认跨任务缓存关闭，配置模型版本后开启；权限仍实时校验
    审核与发布delta 候选 → Prepare → 人工批准 → Commit → OV 回执缺口显式确认；候选编辑使旧批准失效；不绕过已有权限规则

    05 / Agent 直接消费已发布知识

    本体增强检索

    问题 → 可见实体与批准别名 → 原文检索 → 关联事实与证据。没有匹配本体时明确区分普通文档结果。

    POST /api/v1/enterprise/ontology/search

    有边界的结构化诊断

    类型查询 → 时间与限定条件 → 受限规则 → TRUE / FALSE / UNKNOWN，加独立冲突状态。未查到不等于不存在。

    query → compose / evaluate → explain

    这些是既有 OV 企业扩展能力，本次未改动。HTTP 与 MCP 共用认证和事实服务；固定 generation，文本与 ContextPacket 使用同一事实集合。业务写操作不开放。

    06 / 价值、适用场景与不足

    减少重复阅读

    首次一起提议 Schema 和事实。确认后的普通转换无需模型；实际 Token 和耗时收益仍要实测，不能只根据设计判断。

    降低上游合并负担

    用 Skill 和固定 HTTP 契约适配，不向 OV 编译循环加入本体分支。仍需持续运行原生 Compile 回归与契约检查。

    把不确定性留给审核

    失败资料、缺口、冲突、证据歧义可追踪；响应丢失不会自动重复提交模型任务。

    适合企业 Wiki、履约流程、规则说明及需要证据追溯的知识运营。限制包括人工 Schema 评审成本、单并发编排吞吐、持久化大草稿的存储成本，以及模型输出不稳定带来的返工。

    原生任务列表不是永久对账档案：记录不可见时需要人工核查。工作目录暂不自动清理。受限 ACL 是资料访问边界；有工具执行能力的 Compile Runtime 仍必须作为可信服务运行，Skill 不能代替执行环境隔离。

    07 / 已实现与尚待验证

    本地验证

    模型桩与 HTTP 契约测试覆盖目录分页、中文路径、超过 100 KB 的正文、Schema 确认、局部补编译、响应丢失与权限拒绝。隔离 PG 验证幂等受理、重启保存和取消围栏。OV 原生 Compile 相关回归 26 项通过。

    完整命令、版本、计数和既有失败见验收记录，不把桩测试标为真实抽取。

    未验收

    本轮未运行真实模型的原生 Compile 全链路，未部署 SIT / PRD。实际 Runtime、模型、Skill 安装、ACL 检索拒绝与大规模 Token 成本，需要在目标隔离环境验证。

    历史版本曾有真实模型抽取记录，不能用于证明本轮新 Compile 流程已通过。

    启用前需要什么

    先配置两侧 PG、trusted Root Key 和租户本体授权；再准备 OV 原生 Compile Runtime 与有效模型，安装版本固定的 Skill。TE 工作台“构建”支持填写编译 Skill URI，留空使用 viking://agent/skills/ontology-extraction-v1（可由服务默认配置调整）。路径随任务保存，恢复时不变。TE 配置 compile_skill_uri、compile_workspace_uri、独立 compile_user 与等待期限。普通用户应被工作区 ACL 拒绝。模型不再继承 TE 的 ontology.model。
