# 多轮 Skill 挖掘与人工补证

默认新任务使用 `te-native-mining.v1`：TE 管理来源、任务、人工补证与验收；每轮由一个 OV Compile 根据编译 Skill 完成方法规划、归并、正文及案例生成。内部可以有多个模型调用和子任务。

首轮完整构建，后续轮次增量更新同一个远端产物目录。原始材料只在开始时冻结；之后修改源目录不会改变已有任务的输入。每轮使用冻结的编译 Skill 和语言策略。

## 创建任务

在知识源页面选择带有 Skill 用途标签的目录，创建任务。

| 设置 | 行为 |
| --- | --- |
| 最大挖掘轮数 | 1–5，默认3；表示上限，不强制执行空转轮次 |
| 人工补证 | 有真实问题时等待；问题为0时跳过补证并结束当前挖掘 |
| 每轮运行期限 | 60–7200秒，默认3600；保护预算，不代表预计完成时间 |
| 自由挖掘 | 方向选填，按材料支持的完整独立方法组织产物 |
| 单 Skill 整合 | 方向必填，围绕一个完整目标整合步骤和情境参数 |
| 指定数量 | 目标1–100，方向选填；来源不足时说明，不拆碎或强行归并 |

Compile 使用 OV 的模型和运行环境。减少外部 Compile 次数不等于减少全部模型调用；正文、评测与案例工作量也影响耗时。

## 能力拆分与候选集合

编译 Skill 根据触发条件、完整步骤、适用范围和独立终态组织方法。人物、金额、渠道和场景编号通常是参数或分支。不同客户的参数差异不能自动判为来源矛盾。

每个方法在 `compiled_skill/<slug>/` 交付 `SKILL.md`、`EVALUATION.md`、`benchmark.json` 和 `METHOD.json`。方法回执包含任务、触发、输入输出、边界、来源和补证问题；宿主确定性汇总为 `analysis/capability-plan.json`，契约仍为 `skill-miner.plan.v1`。

`benchmark.json` 使用 `team-replay.dataset`，每个方法12个案例，各有至少12条输出完成条件及一条过程条件。宿主从已校验的JSON渲染 `BENCHMARK.md`，不重复让模型生成等价展示文本，也不补造案例或条件。

非方法内容以 `analysis/notes/*.json` 说明处置和来源。纯事实、方向外内容不自动产生补证问题。没有完整方法时保留说明，不能提交候选。

增量归并通过 `METHOD.json` 的 `supersedes` 明确声明被替代的既有方法，宿主验证引用和循环，不按相似度决定合并。旧文件保留在远端与本地谱系、轮次归档中。新方法仍须完整整合有效步骤、条件和来源。

## 复核与补证

1. 查看方法正文、评测和Test Dataset，核对任务边界、情境差异及原文条件。
2. 对真实问题填写回答和来源；不能确认的标为未解决。
3. 按需上传材料、填写复核意见，或编辑允许修改的当前产物。
4. 继续后冻结本轮增量输入，启动下一次Compile。

问题为0时直接结束，并记录独立的 `skipped_checkpoints`；不伪造管理员批准，不产生新Evidence。缺失或非法的回执不能被当作0个问题。跳过补证不代替 True Replay 或 Candidate Review。

关闭人工补证时完成当前轮并保留未解决问题，不自动执行没有新增Evidence的下一轮。

## 下一轮输入

同一个任务保持相同 `to`。下一轮 `from` 包含真实补证、附件、相关原始文件及已变更的产物上下文。问题引用明确时只回读涉及的冻结原文；自由反馈的影响未知时保守回读完整原文。

没有变更的产物不复制成新来源，Compile 按 `against=target` 召回相关历史文件。已编辑产物放在 `revision/`，明确属于修订上下文，不能作事实或案例来源。旧引用身份继续保留并校验，问题本身不是答案。

每轮完整产物和输入独立归档；当前工作区仅在新结果通过确定性校验后切换。原文、受理请求、原始输出和旧版本保留。

## 失败与恢复

- 状态同步失败：保留任务，退避重试；不能因断线创建替代Compile。
- 受理响应丢失：使用原幂等键查询，必要时重发完全相同的冻结请求。
- 远端失败或产物不合格：保留原请求、错误和结果，将明确错误交给整轮修订；每轮最多两次修订，超过则如实失败。
- 确定性校验不放宽中文、来源或案例要求；未知业务事实交给用户补证。

界面显示实际受理的Compile次数和修订次数。工作区切换失败可根据保存版本重试，不覆盖历史。

## 完成与验证

结构验收包括中文展示标题与正文、完整方法文件、引用来源、Test Dataset 格式及独立方法数量约束。它不能证明业务内容正确，也不是 True Replay。

管理员仍按候选选择、True Replay、Candidate Review 和 Publish 的已有门禁使用产物。挖掘不自动发布。

## 历史任务

旧任务继续使用已冻结的单候选或分批协议，原请求与已有产物不迁移。自定义编译 Skill 保持原样；在设置中恢复默认后，新建任务才采用整轮原生编译。
