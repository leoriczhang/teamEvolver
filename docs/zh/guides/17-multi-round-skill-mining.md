# 多轮 Skill 挖掘与人工补证

控制台的 Skill 挖掘由 teamEvolver 管理真实轮次，每轮调用一次 OpenViking Compile。启用人工补证时，上一轮结束后任务暂停，管理员复核本轮 Skill Candidate、回答 Evidence 缺口并补充来源，再启动下一轮。

这条流程使用 OpenViking 上的模型和执行环境；控制台全局模型设置不决定本轮 Compile 使用的模型。原始知识源只在任务开始时冻结，之后修改源目录不会悄悄改变任务输入。

## 创建任务

在知识源页面选择带有 Skill 用途标签的目录，然后创建 Skill 挖掘任务。

| 设置 | 行为 |
| --- | --- |
| 最大挖掘轮数 | 1–5，默认 3；每轮对应独立 Compile 任务 |
| 人工补证 | 启用后，每轮完成进入人工复核，包括最后一轮 |
| 每轮运行期限 | 60–7200 秒，默认 3600；只约束正在执行的一轮，不计算等待人工回复的时间 |

关闭人工补证后，teamEvolver 自动执行设置的轮数。各轮仍保留独立输入、产物和执行记录。最多同时执行 8 个 Compile 挖掘任务；等待人工补证的任务不占执行名额。

## 复核与补证

每轮完成后，控制台展示本轮产物和结构化问题。问题来自 `analysis/review.json`，与 `analysis/gaps.md` 中的 Evidence 缺口对应。每个问题有独立标识、问题说明、需要补证的原因、来源引用和是否必答。

1. 查看 `SKILL.md`、`EVALUATION.md`、`BENCHMARK.md` 和 `benchmark.json`。`benchmark.json` 是统一 `team-replay.dataset` 格式的 Test Dataset，用于后续 True Replay。
2. 对问题填写回答，可填写有权访问的 OpenViking 来源引用。无法确认的问题应明确标记为未解决。
3. 按需要上传补充文档，并填写对本轮产物的复核意见。附件先保存在任务本地目录；点击继续之前不会写入 OpenViking。
4. 点击继续后，teamEvolver 冻结下一轮输入并启动新的 Compile。达到轮数上限时，只能完成最终复核或结束任务。

问题清单为空时，启用人工补证的任务仍等待人工确认，管理员可以直接继续或结束。浏览器刷新或服务重启不会丢失等待状态和已保存附件。

## 下一轮输入

每轮输入包含三个职责清楚的部分：

- **原始 Evidence**：任务开始时冻结的知识源快照。
- **人工补证**：累计回答、来源和补充文档，并保留提交人和时间。
- **修订上下文**：上一轮 Skill 正文、Test Dataset 的案例标识及本轮复核问题和意见，帮助模型进行定向修订。

Compile 的 `from` 只包含冻结的来源 Evidence 和人工补证目录。修订上下文以已提供的引用文本放入 `instruction`，不会作为来源文件重新执行提取，也不能用于 provenance 引用。完整的上轮七个产物仍保存在本地和远端轮次归档中；不把完整 Test Dataset 和重复 Markdown 内容再次放入提取输入。

传给模型的修订上下文 JSON 最多 30000 字符。超过限制时压缩问题、复核意见或 Skill 正文，并明确记录节选和省略标记；完整内容仍保留在归档中。节选不意味着要求模型使用工具寻找剩余文件。

上一轮模型产物不作为已证实的 Evidence。模型必须引用原始来源或人工补证来源；人工回答与原文冲突时应保留冲突，不以新回答自动覆盖原文。

每轮使用独立输出目录，避免上轮文件遗留。控制台保留各轮的远端任务 ID、输入引用、产物、校验结果和耗时，可查看不同轮次的结果。

## 结束与后续验证

在人工复核阶段可以提前结束；最后一轮也需要完成最终复核。结束时可保存复核意见和未解决的问题。若还有 Evidence 缺口，最终 Skill Candidate 保留“需复核”提示。

最后一轮完成后补充的内容不会自动修改本轮产物；需要把这些内容纳入产物时，应在尚有轮数时继续挖掘，或创建新的任务。结束挖掘不会自动 Publish。最终 Skill Candidate 继续进入现有 True Replay 和 Candidate Review 流程。

Test Dataset 结构校验确认文件契约正确，不证明业务事实、数值比较或回答条件正确。多轮补证提供修订机会，管理员仍需检查来源与产物是否一致。

OpenViking 的 `completed` 也可能表示部分来源处理失败后保留了可用产物。即使七个必需文件齐全且格式通过，也不能据此认定所有 Evidence 已被处理。控制台在人工复核、轮次历史和最终产物质量中保留这类警告，并将当前产物标记为“需复核”。例如，一份源文档提取失败时，另外两份文档仍可能生成七个完整文件。

遇到来源遗漏时，应检查警告涉及的文档并补充复核意见；继续下一轮会重新处理完整的原始冻结知识源和累计补证。上一轮候选仍只是修订上下文，不能代替漏处理的原始 Evidence。后续轮次的结果需重新检查，历史警告保留在对应轮次记录中。

## 恢复与停止

teamEvolver 在本地持久化轮次、人工复核和提交状态。服务重启后恢复现有轮次的远端状态，不重复创建已受理的 Compile。网络中断导致受理结果未知时，使用同一轮的幂等键查询或恢复提交。

每轮首次准备时还会冻结本轮编译 Skill 正文和输入归档。编译器安装到名称包含来源正文摘要的独立 Skill URI，记录 `compiler_source_sha256`、实际安装正文的 `compiler_sha256` 和 `compiler_uri`。已存在的版本仅在正文一致时复用，内容冲突会停止提交，不覆盖该版本。

该轮重试使用相同的编译器 URI、正文、输入和 Compile 请求。受理结果未知且远端尚未记录任务时，可以用已冻结正文恢复缺失的编译器包；已记录任务则直接恢复状态。服务更新或其他任务安装新编译器，不会改变本轮绑定的版本。

停止执行中的任务会请求 OpenViking 协作取消，等待远端终态。人工等待阶段可以直接结束。删除任务前应先停止正在执行的任务。

接口和错误说明见 [Skill 挖掘 API](../api/17-skill-mining.md)。实现位于 [任务仓库](../../../team_miner/ov_compile_mining.py) 和 [主服务桥接](../../../team_miner/bridge.py)。
