# 多轮 Skill 挖掘与人工补证

Skill 挖掘把登记在 OpenViking 中的资料编译为可交付的 Skill 包，代码位于 `team_miner/skill_miner/`。当前默认编译器按课程原表中的知识点构建或局部修订教官 Skill；它不生成验证案例，也不自动发布。知识库挖掘独立位于 `team_miner/knowledge_miner/`，继续执行资料到 Wiki 的流程。

控制台保留「挖掘总览」「知识源」「Skill 挖掘」三个入口。任务采用冻结的编译 Skill 和输入，后续修改原始目录或默认指令不会追溯改变已受理轮次。

## 前置条件与持久化

- 已部署 API 与 Worker，且当前租户的 `miner` 模块配置存在；缺失时返回503，不回退本机 YAML。
- 当前身份为租户 `tenant_admin` 或平台 `platform_admin`，并已连接租户的 OpenViking Account。
- 任务、轮次、附件和制品内容持久化在 PostgreSQL；OpenViking 保存知识制品与 Compile Task，工作目录仅作可重建缓存。
- Skill 挖掘默认值与编译指令单独保存于 PostgreSQL。配置保存和恢复默认使用独立 `revision` / `expected_revision`，过期版本返回409，不覆盖他人的更新。

上传、产物保存等长操作返回202及后台任务回执；控制台等待完成的 `result` 后才显示保存成功。失败、取消或缺失结果不能当作成功。接口见 [Skill 挖掘 API](../api/17-skill-mining.md)。

## 创建任务

在「知识源」登记目录并添加 Skill 用途标签，然后从「Skill 挖掘」创建任务。

| 设置 | 行为 |
| --- | --- |
| 最大挖掘轮数 | 1–5，默认3；是上限，不强制执行空转轮次 |
| 人工补证 | 采用评审问题契约的任务遇到真实问题时等待；默认完成交付模式不以人工批准作为完成条件 |
| 每轮运行期限 | 60–7200秒，默认3600；保护预算，不代表预计完成时间 |
| 自由挖掘 | 方向选填，由所选编译 Skill 依据材料组织产物 |
| 单 Skill 整合 | 方向必填，目标数量固定为1 |
| 指定数量 | 目标1–100，方向选填；来源不足时说明，不强行拆分或归并 |

Compile 使用 OpenViking 的模型和运行环境。一次外部 Compile 可以包含多个模型调用和内部子任务，外部请求数量不能直接代表实际工作量。

## 默认交付与修订

默认编译器为 `team_miner/skill_miner/knowledge_compiler_v8.py`，执行协议使用 `te-native-mining.v1`，完成策略为 `te-compile-finished.v1`。远端完成后保留返回文件并记录挖掘成功，不增加 TE 内容验收，不要求 `EVALUATION.md`、`METHOD.json`、`benchmark.json` 或验证案例。

任务清单显示 `content_validated=false`，对应候选显示 `can_submit=false`。这表示完成了挖掘交付，不能据此认为业务内容正确、True Replay 通过或可以发布。

管理员可以查看、编辑当前产物；在轮数上限内，有明确的补充修订要求时可继续下一轮。继续时冻结修订要求、附件及必要的原文和前轮上下文，增量更新同一远端目标。没有修订要求时不能自动空转；旧文件和轮次归档保留。

## 完整候选的复核与补证

显式采用候选评审契约的任务仍支持独立方法、能力计划和 Test Dataset：

- 完整包包含 `SKILL.md`、`EVALUATION.md`、`benchmark.json`、`BENCHMARK.md` 和实际返回的引用或脚本文件。
- `benchmark.json` 使用 `team-replay.dataset`，每个独立候选有12–24条案例，每个案例有12–24条输出条件及至少一条过程条件。
- 能力计划按可独立执行的任务边界组织候选；纯事实或来源不足时保留处置说明，不能补造方法。
- 人工复核时填写具体回答与来源，不确定的问题明确标为未解决；可以附加材料、反馈或编辑允许修改的当前产物。
- 仅有合法且真实的空问题回执时可跳过人工补证；回执缺失或格式错误不能被当作零问题。

默认只完成交付的包不能通过补造案例进入这条评审流程。

## 提交与发布边界

只有任务已经完成且当前独立候选通过完整产物与 Test Dataset 校验时，才可提交到既有 Candidate Review 入口。一个候选不完整不会阻断其他完整候选；提交保留整包资源，不只传一个 Markdown 文件。

同一原始包重复提交返回同一候选，不重置验证或人工评审。已有不同的同名待评审候选时，已受理的后台任务进入 `failed` 并返回冲突 `error_code`，需要先处理已有候选。旧案例的内联材料会在候选包中转换为可核对的真实材料文件，Replay 两个分支读取相同内容；原始挖掘包保持不变。提交只创建 `open` 候选；True Replay、Candidate Review 与 Publish 继续采用主平台的门禁，不自动发布。

文档来源 URI 保留为 Evidence，不能当作真实 Session。Compiler 指定的 Session、私有 Context、运行时或 Adapter 不会决定回放身份；执行由租户已配置并冻结的 Replay Adapter 完成。

## 失败与恢复

- 状态同步失败时保留最后已知状态并退避重试，不能因断线创建替代 Compile。
- 受理响应丢失时使用原幂等键核对同一请求，不能不加区分地重新提交。
- 用户停止后等待远端取消或终态确认，不能把本地停止意图当作远端已停止。
- 采用验收契约的任务仅对已识别的格式、产物不完整或输出截断按有界策略修订；原请求、错误和结果保留。
- 缺少配置、PG 或 OpenViking 不可用时如实失败；本机缓存不能替代权威状态或远端结果。

任务详情中的轮次、Compile 回执、耗时、补证与归档分别反映各自事实。完成回执、格式检查和本地测试都不能替代真实业务使用或 True Replay。

用于这些文档案例的租户 Replay Adapter 必须支持 `document` 运行类型与没有来源 Session 的独立执行。仅支持特定来源运行类型的 Adapter 会返回不支持；不能伪造来源 Session、私有 Context 或改选其他 Adapter 来通过验证。适配器兼容性必须单独实测，固定本地测试 Factory 只能验证接口连通性。
