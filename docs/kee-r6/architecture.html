KEE：把方法、记忆与能力放在一个平台

统一入口，保留现有模块；方法批准后导出 Wiki，Agent 继续通过 OpenViking 读取。

职责架构数据流签收案例核心实现场景与边界验收

谁负责什么

KEE（现有 TE）

来源冻结、结构和方法编制、人工审核、任务恢复、Wiki 发布与审计。包名、CLI、PG schema、租户与 Skill ID 保留。

OpenViking

通用内容、ACL、检索、索引与原资产。默认不注册本体扩展；历史表不自动删除。

既有 Agent／业务系统

读取方法后按原 Skill 与业务授权办事。UpClaw 本轮零改动，无调用前后拦截器。

统一的是运营入口。团队 Memory、Skill、方法 Wiki 和成功经验资源仍有各自的维护者和生效规则。

六导航／三布局视角→现有租户与权限→KEE 模块与 Compile Port→隔离模型 Worker

结构、冻结正文、候选、审查和恢复检查点存既有 PG；已发布 Wiki 通过 OV 通用 HTTP 接口交付。Worker 只获得模型输入与必要模型配置，OV Key 留在可信后端。

主要数据流

Viking 文件／目录／上传→逐文件冻结与准确引文→同次提议 Schema 与方法→确认／编辑／证据审核→Prepare → Approve → Commit→不可变 Wiki → 回读 → 索引 → 入口

澄清要求进入输入摘要；确认后沿用已核验结构，正文和反链确定性生成。编辑改变摘要，使原批准失效。

资产既有数据流及生效边界
SkillSession/Evidence → Skill Evolution → True Replay → Candidate Review → SkillMutationService → Agent 拉取。
团队 Memory私有快照 → 聚合 Compile → 私有快照 → DreamCycle 维护；仍由 team_memory 唯一维护。
成功经验PG 真源 → 稳定正文摘要 → 固定 OV 资源；动态计数不触发上传，不等于 Skill／方法发布。
方法 WikiKEE 批准包与版本／审计权威；OV 实际内容、ACL、索引分别确认。没有整包原子保证。

一次合成签收核验

资料：“签收必须核验授权。未经授权不得签收。异常件应升级处理。”这只是测试资料，不代表正式业务制度。

  1. 运营者冻结原文，记录 revision、SHA 和 Unicode 引文位置。
  2. 输入澄清“保留禁止事项、例外和完成标准”；Compile 同次提出 Schema 和方法。
  3. 审核主页面必须包含授权条件、禁止签收、异常升级与可追溯完成标准；引用已有 Skill 时核实真实 ID／版本。
  4. 批准同一摘要，上传私有版本目录；回读、核对 ACL 与索引，再切换阅读入口并保存回执。
  5. Agent 经 OV 读取方法，具体签收仍由原业务工具授权；KEE 不代为执行。
  6. 来源撤销先围栏并收紧 ACL，随后清理整个版本。回滚创建新候选并重新审核。

核心模块怎样实现

模块实现机制
sources.py / store.py原件读取逐用户 ACL 检查；递归分页、规模预算；来源版本和结构置于 objects 的 kee/r6 前缀，事务内设置租户 RLS。
compile.py / worker.py复用旧任务租约，分批检查点，隔离子进程、有界模型调用与全进程并发8；无 OV 凭据和工具。
contracts.py / references.py四版本化契约、准确引文、Schema 版本、真实 Skill 和既有个案引用；不复制轨迹，不创建第二注册表。
service.py候选编辑、Schema 确认、摘要批准、五分钟有效期、版本基线、取消代次与恢复。
wiki.py / publish.py同源正文／引文／反链、文本转义、不可变版本；回读摘要、等待索引、目标锁、入口回执、整个版本撤回。
Memory Port复用 AggregationState 与目标锁。先存模型输出再写内容，索引恢复无需第二次模型调用；受限模式不执行 Skill 工具。

值得保留的设计

人和 Agent 共读同一批准版本；结构与正文避免两次模型改写。把“已上传”“已索引”“已发布”分开，使故障有明确恢复点。版本与审查复用现有状态，避免治理方案带来第二套运行账本。

适用场景、长处与不足

适用

制度、SOP、跨文档方法整理；需要专家核对条件和引用；多人持续维护 Wiki，并与 Memory／Skill Evolution 配合。

长处

复用登录、权限与现有进化模块；证据可定位；确认后无模型改写；固定版本、未知状态对账与取消围栏。

不足

OV 无包级原子性；人工 JSON 编制仍偏技术；简单静态 check 不覆盖动态业务语义；大型／工具型 Memory Skill 需另验收。

尚未实现：业务工具前后核验、UpClaw 可靠投递、完整澄清分派／语义 Schema／局部补编译、集群模型配额。既有通用知识库挖掘旧 Compile 执行器保留兼容。不能将蓝图或模型桩结果报告为业务收益。

默认 query/check 关闭且不注册 MCP；无证据为 UNKNOWN，明确反证才为 FALSE；冲突单列。普通 Agent 读 Wiki 不依赖 KEE 在线；方法撤回需要 KEE 与 OV 具备可用连接。

验证与未执行事项

真实隔离非特权 PG／RLS + OV HTTP 契约桩、新接口安全与故障测试、Memory 检查点恢复、生产前端构建和离线校验。真实 TE＋隔离子进程模型桩完成发布读取，模型一次调用。

全量回归的既有失败、真实模型凭据缺失、浏览器完整流程受阻、真实 OV 索引／生产迁移未执行均见验收册。
