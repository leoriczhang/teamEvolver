## 接口与参数

前缀 `/kee/v1`。JSON 请求须 `Content-Type: application/json`，最大 8 MiB。领域写操作限当前租户管理员／有效支持模式；读取限现有 `team.read` 与对象读者范围。

| 方法／路径 | 请求或作用 |
|---|---|
| GET /capabilities | 执行器、三视角、可选结构接口状态；无执行拦截 |
| POST /sources | roots[] 文件／目录、uploads[{name,text}]、readers[] TE 用户（最多20） |
| POST /documents | filename、content_base64、source_id、readers；复用 PDF/Word/Excel 等解析器，不经过 OV 本体 API |
| GET /sources/{id} | 冻结原文、摘要与逐项缺口；仅管理员且在读者范围 |
| POST /sources/{id}/revoke | 先围栏和阻断依赖版本，再在原队列清理；可能返回 cleanup_jobs |
| POST /methods/build | contract=kee.method-build.v1、submission_key、collection_id、pack_id、clarification；202 |
| GET /methods/jobs[/{id}] | 当前主体任务与旧执行器历史，保留 ID |
| PUT /methods/jobs/{id}/candidate | expected_digest、candidate ProcedurePack；使旧批准失效 |
| POST /methods/jobs/{id}/confirm-schema | expected_digest；确认后确定性导出 |
| POST /methods/jobs/{id}/prepare | target_uri 安全 resources URI、readers[]；校验来源、引用、基线 |
| POST /methods/jobs/{id}/approve | note、acknowledge_gaps；五分钟有效 |
| POST /methods/jobs/{id}/commit | commit_key；202/queued 仅受理，不代表 published |
| POST /methods/jobs/{id}/retry、cancel、withdraw | 恢复对账、取消围栏、整个版本撤回 |
| POST /methods/jobs/{id}/rollback | commit_key；新任务／新版本，重新 Prepare 与批准 |
| GET /methods/jobs/{id}/export、impact | 文件与结构导出；变化列表、来源／链接数量 |
| GET /wiki/releases?after=... | 按 key 分页100；只返回授权读者条目 |
| GET /wiki/releases/{target_hash}/{generation}/pages/{path} | 固定版本、原权限与页面摘要核验；不读取任意文件 |
| POST /feedback | note；只写原审计，不修改资产 |

## 契约及身份

[ProcedurePack](file:///Users/01435552/Project/inc-aiagent-core-team-evolver/team_ontology/kee/contracts/ProcedurePack.schema.json) 包含方法的条件、禁止、例外、步骤、完成标准、引文和 Schema。
[CapabilityBinding](file:///Users/01435552/Project/inc-aiagent-core-team-evolver/team_ontology/kee/contracts/CapabilityBinding.schema.json) 记录既有 Skill ID/version/input/output，Prepare 查询当前租户已有 Skill registry，不新增注册表。
[CaseEvidence](file:///Users/01435552/Project/inc-aiagent-core-team-evolver/team_ontology/kee/contracts/CaseEvidence.schema.json) 只记录引用和元数据；reference 是既有 objects key，如 `sessions/...`、`skill_evidence/...`、`kee/r6/releases/...`。支持／矛盾结论须绑定原记录 digest，不复制轨迹。
[WikiRelease](file:///Users/01435552/Project/inc-aiagent-core-team-evolver/team_ontology/kee/contracts/WikiRelease.schema.json) 分别记录上传、索引等待、入口未知、生效、撤回；回执 `package_atomic=false`。

## 示例

```bash
curl http://127.0.0.1:52010/kee/v1/sources \
  -H 'Content-Type: application/json' -H 'X-Tenant-Id: demo' \
  -H 'Authorization: Bearer <已配置的可信后端凭据>' \
  -d '{"roots":["viking://resources/wiki/handover"],"readers":["运营用户ID"]}'
```

生产优先使用已登录控制台；Root Key 永不下发浏览器。服务 Root 主体只可声明自身读者；多人运营走现有已认证用户映射。

## 可选结构读取

只保留 POST `/ontology/query` 和 `/ontology/check`，`ontology.kee_query_enabled` 默认 false。未开启返回404，不暴露 MCP。query 固定 generation，扫描最多10000、结果最多100、求值时间最多1000ms。check 使用 subject/predicate/expected 精确条件，返回 TRUE/FALSE/UNKNOWN、conflict、gaps、facts、generation、截断与 caller_supplied 非权威标记，`execution_authorized=false`。

首期不执行递归规则、任意推理、动态业务事实或跨案核验。方法中的时间／限定条件保留在正文，简单静态 Fact 检查不覆盖全部业务语义。

## 状态与错误

`queued → running → schema_review → review_ready → prepared → approved → queued → published`；导入回滚候选为 imported；取消 cancelled；异常 failed；撤回 withdrawn。索引等待体现在 result.release.state，不伪装成已发布。

| 状态／错误 | 处理 |
|---|---|
| 403／SOURCE_REVOKED、READER_MEMBERSHIP_REQUIRED | 检查当前租户及原件／Wiki ACL，不改浏览器身份头绕过 |
| 409／CANDIDATE_DIGEST_CONFLICT、VALID_APPROVAL_REQUIRED | 重新读取、编辑、Prepare 和审核 |
| 409／WIKI_BASELINE_CONFLICT_REAPPROVAL_REQUIRED | 基线变化，重新审核；不自动覆盖 |
| 409／WIKI_DEADLINE_MANUAL_RECONCILIATION_REQUIRED | 对账实际正文、索引和入口，撤回清理后重新构建 |
| 413／SOURCE_*_LIMIT、STRUCTURE_SIZE_LIMIT | 拆来源集合，不静默裁正文 |
| 422／SOURCE_EVIDENCE_MISMATCH、CAPABILITY_SKILL_VERSION_NOT_FOUND | 修正证据字符位置或实际引用 |
| 429／ONTOLOGY_QUEUE_FULL | 队列最多32，延后重试 |
| 503／WIKI_INDEX_NOT_CONFIRMED | 原任务继续对账，不重编译／重写相同正文 |
| 410／KEE_R6_USE_METHOD_BUILD | 原生 R6 安装退出旧新建本体路径；旧任务查询取消保留 |

原生安装的旧 `/te/enterprise/v1` 写操作统一返回410，取消除外；capabilities 返回后续接口指引，不继续调用已退休 OV 本体能力。旧任务保留查询／取消，其他历史源和资产需按迁移工具导出核验，不能将接口路径保留理解为仍有旧 OV 写者。

## 部署材料

本轮不部署。保留原 TE PG、objects/RLS、租户和服务凭据配置；OV 通用服务继续使用其原 PG 与认证。无需 Ontology 独立库、签名密钥或独立 Runtime。

```yaml
compile:
  executor: internal
ontology:
  enabled: true
  model: {} # 继承 TE 租户有效 llm；可按需覆盖 model/base_url/api_key
  allow_fixture: false
  kee_query_enabled: false
  kee_max_model_calls: 64
  kee_compile_deadline_seconds: 480
  state_dir: /app/deploy/logs/ontology
```

`TE_ONTOLOGY_ENABLED` 仍可覆盖 enabled。compile 是服务级选择，不允许租户改执行器。根目录来源预算仍1000文件、20层、10000条目、20MiB总量、2MiB单文件；冻结及一次权限核对约110秒期限。文件失败404有界重试后记录缺口，身份／服务／预算错误中止。

模型调用每批最多80000字符、总计最多64批、整体480秒，每个隔离进程最多70秒；全部 TE 模型调用单进程上限8。不自动配置真实模型额度。隔离子进程依赖与 TE 使用同一 Python 环境，需包含 openai。

工作目录自动创建；不是日志目录。日志仍由服务级 logging 配置控制，SIT／PRD `/app/deploy/logs`，敏感内容不打印。配置或代码变更后重启，先排空任务并确认端口释放。

OV 账户必须真正启用 ACL，运营主体具有 manage。发布器先设置 restricted，并用另一普通身份 stat 探测403；若 ACL 被关闭，不允许上传私有方法正文。编译在 PG 私有来源上运行，不需要 OV Ontology Skill。

## 操作步骤

1. 知识与方法 → Ontology 与方法 Wiki：填写 Viking 文件／目录或上传一个文档，指定可读 TE 成员。所有成员须能读取每个原件。
2. 输入方法包标识与澄清要求，启动内部 Compile。来源、方法、准确引文及 Schema 同屏查看。
3. 修改结构后保存；确认 Schema。确认不再调用模型，覆盖缺口须显式审核。
4. 填写 Wiki 发布 resources 目标；Prepare 核验当前权限、证据、真实 Skill／个案引用与基线。
5. 人工批准并填写意见；五分钟内 Commit。等待状态 published 及回执，不能将 queued 或索引等待报告为发布成功。
6. 只读区读取固定版本或让 Agent 通过 OV 原入口读取。反馈进入审计，不改变批准结构。
7. 回滚创建新候选，重新审核；撤回整个版本先收紧ACL、递归清理目录，再核验404。来源撤销会围栏旧任务并派发清理。

公开 Wiki、原件、候选并非相同可见范围。反链只从同一批准包生成；主页面完整保留否定、例外和完成标准。OV Admin／Root 的特权读取不构成普通 Agent ACL 测试。

## 恢复与限制

已有 ontology_jobs/outbox 的租约660秒、attempt围栏复用。running 检查点保留 pending，重启可重新领取；取消后迟到结果不能覆盖新状态。支持模式到期时恢复需重新认证，人工重试保存当前有效支持上下文。

发布正文用固定不可变 URI；504、响应丢失先回读摘要，不盲目写第二遍。索引未就绪只继续wait／consistency。目标 pending intent 保留防止另一任务覆盖；30分钟后转人工对账。不要手工删除 pending 或清同步库。

跨 TE/OV 没有分布式／包级原子提交：目录ACL开放、索引与入口切换可能有窗口。权限收紧失败、OV 离线时撤回不能报告成功；保留任务，恢复后继续对账。OV 递归 rm 的检索清理仍须真实部署验收，不把模拟 HTTP 通过视为真实索引验证。

Memory 两阶段流程和 SkillMutationService 不变。内部 Memory Port 保存模型输出到既有 AggregationState，索引恢复不重调模型；只支持受限正文输出，不执行工具型 Skill，不新增自动物理删除保证。通用知识库挖掘旧执行器仍保留兼容入口。

## 迁移干跑与回滚

先暂停旧 Worker／受理，排空或取消在途任务，导出并备份旧表。工具默认干跑，DSN 只从指定环境变量读取，禁止写入命令或文档。

```bash
python scripts/kee_migrate.py export --dsn-env OV_MIGRATION_DSN \
  --account product_agent --output /secure/ov-history.ndjson --receipt /secure/export.json
python scripts/kee_migrate.py import --dsn-env TE_MIGRATION_DSN \
  --account product_agent --tenant '<TE租户ID>' --schema teamevolver \
  --input /secure/ov-history.ndjson --receipt /secure/import-dry-run.json
```

检查 counts、账户、摘要及每条映射后才显式加 `--apply`。导入前缀 `kee/r6/history/ov/<account摘要>/...`，不重新发布、不删原表；旧事实缺少方法／证据时 requires_enrichment。rollback 使用相同输入先干跑，再 apply，仅删除摘要完全相同的本轮导入对象。历史版本、批准、撤回记录保留在导出与映射中。

OV 新安装默认不注册本体扩展（旧环境变量也不触发）。已有表、模块、历史 MCP 源码不自动删除。回滚代码前须停止 KEE 新任务、核对公开 Wiki 与入口；旧 OV 专用 Ontology 版本不会因回滚自动成为最新方法版本。
