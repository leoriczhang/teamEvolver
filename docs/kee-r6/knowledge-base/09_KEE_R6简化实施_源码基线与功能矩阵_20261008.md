# KEE R6 简化实施：四类知识资产与源码基线

日期：2026-10-08。本文为个人知识库待本人审核贡献，描述本地源码和验证，不表示 SIT／PRD 已部署。

## 平台与四类资产

统一 KEE 承载运营控制面，保留 teamEvolver 的 Python 包、CLI/API、ID、数据库 schema 与旧入口；OV 是通用内容、权限、检索、索引后端。六导航为工作台、智能体与能力、知识与方法、进化与实验、审查与发布、设置与接入。三视角仅布局差异，权限沿用认证和租户上下文，普通读者只读。

| 主题 | 真源、写者与数据流 | 本轮边界 |
|---|---|---|
| 企业知识库 | 资料→通用 OV 内容与索引→Agent 认证检索读取；KEE 统一来源和运营界面 | 原生 ACL／认证不重建；不声称普通资源已经通过本体审批 |
| 团队 Memory | 私有快照→聚合 Compile→DreamCycle 维护 Compile→原维护入口更新目标 | 使用受限内部 Port 与原 AggregationState 检查点；无包级原子发布或工具型 Skill 等价保证 |
| Skill Evolution／True Replay | Session/Evidence→候选生成→True Replay→候选审核→SkillMutationService→Agent pull | 唯一 Judge、唯一 Skill 发布入口；pull 保留版本和 tombstone，不新建 delivery outbox |
| Ontology／方法 Wiki | 递归冻结→澄清→隔离 Compile 同次提出 Schema 和方法→证据审查→Schema 确认→批准→确定性 Wiki→OV 读取 | 结构与审批归 KEE，Wiki 内容归 OV；不再依赖 OV 本体资产表或独立 Runtime |

成功经验同步继续以 PG 经验 JSON 为真源，OV 只是增量资源副本；正文摘要排除统计。存量导入、同步、Skill 发布和方法发布是不同机制。现有内容身份去重不等于语义去重；本轮未清理线上重复经验或验证历史索引积压已经恢复。

UpClaw 不修改，不新增调用前后检查、可靠投递队列或第二套 Session/Judge。可选 query/check 默认关闭、不注册 MCP，不参与业务授权。

## 主数据流与一个案例

合成签收核验原件逐文件冻结为内容摘要版本，异步构建用既有租约任务和隔离模型子进程。输出方法要保留“有争议时不得直接认定本人签收”、例外和完成标准；KEE 对准确引文、Unicode 位置、真实 Skill 版本与个案引用进行确定性核验。确认 Schema 后直接导出，同一批准结构生成主页面、证据页、双向方法链接和结构包，不再调用模型。

人工审核绑定候选、来源状态、基线和权限。改候选后旧 Prepare／批准失效；Commit 仅受理，直到回读、ACL、索引、入口与回执确认才显示已发布。Agent 通过 OV 阅读，同身份受当前 ACL 约束，不触发业务写动作。

## 适用场景与代价

适合可人工审核、需保留条件／否定／例外和来源的流程规范、签收核验、履约异常与企业方法库。长处是复用现有平台、结构和正文一致、审查可追溯、发布可对账、减少新增服务与持久化。代价是人工结构审查、私有证据权限核验和索引等待成本；OV 没有包级原子提交，真实模型准确率、索引吞吐与业务效果尚未证明。

## 核验结果与实现选择

- 原控制台已有单登录、租户权限、Workspace、Skill Evolution、True Replay、Memory 与 SkillMiner；采用菜单映射，不重建身份或资产注册表。
- 原 Ontology 工作台依赖 OV 专用资产接口与原生 Compile。R6 方法任务改用 KEE 内部 Port 与隔离子进程；新结构使用现有 PG objects，原任务、审核、审计表复用。
- 初始 pytest 收集缺失 `team_skills.evolution.runtime`。该目录在历史提交 `e8a802b` 被删除，但当前 entry/mixins 仍引用它。本轮从该提交父版本恢复唯一实现，并适配当前 Evidence、pattern_refs 与候选描述契约；未新建第二套 Judge。
- OV 默认扩展注册移除 Ontology；历史代码、表与专门测试入口保留。通用 Compile 内部循环及 UpClaw 保持原样。
- 旧 Ontology 任务仍可按原执行器查询、取消。原生安装的新建旧本体 API 返回 410，指向 `/kee/v1/methods/build`；独立 legacy 适配测试仍支持旧契约。迁移时先停止旧受理，不能混用两个正式写者。

## 明确差距

三种视角首期只调整导航顺序，尚非三个完全定制首页。方法编制采用同屏 JSON 编辑、来源与证据对照及文本澄清；复杂逐项澄清分派、完整语义 Schema 校验、自动局部补编译不在本轮实现。

内部 Memory Compile 为受限 JSON 输出模式：1 MiB 输入、128 输出页、最多两次模型尝试，不执行 Skill 脚本或工具。既有大型／工具型 Skill 需单独兼容验收；不能将该适配报告为与 OV Agent 循环等价。

既有通用“知识库挖掘”的 OV Compile 接口保留其原执行器兼容路径，本轮迁入的是新方法构建与 Memory Port。SkillMiner 保留现有流水线，Skill 发布仍唯一走 SkillMutationService。

历史 Ontology 迁移工具保留结构、版本、证据、批准及撤回原记录，按账户映射到 KEE 历史前缀。缺方法定义的旧事实不会被猜测为 ProcedurePack；进入待补证历史区，需运营人员明确构造方法后重新审核。


# 功能映射与回归矩阵

| 一级导航 | 保留功能／路由 | R6 行为 |
|---|---|---|
| 工作台 | 运行总览、实验工作台、运行状态 | 原 Session／队列／实验入口保留 |
| 智能体与能力 | 个人与团队资产、平台资产、成员与接入 | Workspace、Skill、Memory 原维护入口 |
| 知识与方法 | 知识源、经验库、知识库挖掘、原 ontology 页面键 | 新 KeeMethodsView；原 OntologyView 留作历史源码 |
| 进化与实验 | 进化链路、挖掘总览、挖掘任务、数据集 | Skill Evolution、True Replay、SkillMiner 原行为 |
| 审查与发布 | 候选评审、审计、链路观测 | 聚合入口链接原维护者，不统一写事务 |
| 设置与接入 | 租户、用户、模型、数据源、使用文档 | 现有身份、服务级配置与租户上下文 |

视角 `agent-manager`、`knowledge-manager`、`research` 只改变布局。权限仍以现有 authenticated user、有效租户成员及平台支持模式校验。读者只能读取授权 Wiki 并提供反馈；直接调用写 API 返回 403。

资产边界：Skill 走 SkillMutationService；团队 Memory 走 team_memory；方法包走 KEE 人工批准与 Wiki 发布；成功经验资源同步保持 PG 真源。上传经验不是发布 Skill 或方法包。

原 Session／Evidence／Judge 不搬迁，不创建 UpClaw 队列或逐单执行库。既有 True Replay 页面和任务保留；本轮没有新注册业务 Skill、外部 Agent Runtime 或真实业务动作。


# R6 决策与工程边界

1. KEE 是现有 teamEvolver 的对外品牌；包名、CLI、租户 ID、数据库 schema 保留。
2. 方法结构、Schema、审批、版本与反馈在 KEE；OV 仅通用内容、ACL、检索和索引。两库无需相同，不直连 OV 数据库执行发布。
3. 四契约存于 `kee/r6/` objects 前缀；SourceRevision 分对象存储，避免全集正文塞入单个记录。审查使用原 ontology_jobs/outbox/audit，不另设 workflow 平台。
4. 内部模型 Worker 仅收到冻结正文、Skill 指令和必要模型凭据，不收到 OV Key，不执行外部工具。TE 全进程模型并发上限 8；多实例集群共享配额尚需运维限制，不能称为集群级全局限流。
5. Clarification 属于构建输入与缓存摘要。批准结构确定性导出，Schema 确认后不新增模型调用。
6. Source、Method、Wiki 引文和反链来自同一批准包。不能使用反链推导新业务事实；源正文作为文本转义，避免注入链接或 HTML。
7. 冻结按文件记录，不是跨文件同一时刻快照。允许发布冻结版本；读取／发布时仍检查当前 ACL，所有发布读者须有原件读取权限。
8. Prepare 绑定候选、页面摘要、来源、读者、基线；Approve 五分钟、人工意见和缺口确认；编辑候选立即作废旧批准。Commit 固定键；发布未知先回读摘要、等待索引，最长自动等待 30 分钟后转人工对账。
9. TE 同目标锁／基线 CAS 保障唯一入口提交；OV 没有包级原子操作，开放目录与入口切换仍存在跨系统窗口。失败保留 pending intent，不能盲目清锁或重写。
10. 撤回先收紧 ACL，再递归移除整个版本；来源撤销围栏任务并派发已有队列清理。旧 URI、引文、反链均位于版本目录，不能只改 index.md。
11. query/check 默认关闭且不注册 MCP；FALSE 必须有明确反证，冲突和裁剪返回 UNKNOWN；没有逐单业务执行授权。
12. 历史表保留，迁移干跑／校验／备份后才可 apply；清理线上旧本体表不在授权范围。
