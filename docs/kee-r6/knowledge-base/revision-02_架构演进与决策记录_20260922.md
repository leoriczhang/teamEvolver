## 决策及理由

**D01：只部署 TE 与 OV。** 不再独立部署 enhancer Runtime。迁入源码、许可证与历史兼容功能保留；新任务不使用旧 TE 直接抽取路径。减少一个独立运维面，不代表取消 OV 原生 Compile Runtime 的运行依赖。

**D02：任务权威分层。** TE 登记运营任务、来源集合和审核；OV 登记与执行原生 Compile。正式资产生效以 OV 回执为准。两个任务 ID 关联保存，不能把其中一个的完成当作全部完成。

**D03：取消强制共库。** TE PG 和 OV PG 只保证自身事务。OV Ontology 可以复用已有 PG 连接来源，但不再因为本体构建而要求它与原生 Compile 同一数据库。独立 DSN 只是可选覆盖。

**D04：Root Key 取代发布公私钥。** `sf.ontology.commit.v2` 用结构化 approval；TE 后端代表审批主体提交，OV 校验真实 Root Key、trusted 模式、审批时效、摘要、权限和基线。保留人工批准；不将普通 admin 请求头当授权。ObservationHandle 的签名与此无关，继续保留。

**D05：原生 Compile + 固定 Skill。** 专用 Skill 同次处理正文产出 Schema 提案及事实草稿；TE 在 Schema 原样确认或明确改名时确定性转换，不重新扫描全部正文。语义变化才补编译；不知道影响范围就全量重编译。收益需实测，不能预填 Token 节省比例。

**D06：目录快照按文件记录。** 不宣称跨文件同一时刻，不跟随范围外链接；冻结原文与当前访问授权分离。输入和草稿先设置受限 ACL，再写正文。

**D07：成功经验固定 URI、排除动态统计。** 以源 key 摘要与经验 ID 定位，以正文摘要判断变化。按用户要求去掉 TE 租户目录层；PG 隔离保留。没有改成目录冻结锁，也没有解决不同租户共享 OV 目标时的所有覆盖问题。

**D08：Account Key 限定普通 Agent 身份。** Root Key 留在可信后端，普通凭据绑定账户与用户。该扩展的测试和交付说明不是现网所有 Agent 已迁移的证明。
