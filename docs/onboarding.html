OpenViking bucket

THE ONLY SHARED THING

真正的共享中心。会话、候选、验证结果、发布的技能, 都汇在这。team AK 是唯一入场券: 谁能读写, 由钥匙决定, 而不是由服务器决定。

你的 teamEvolver

LOCAL PROXY · PEER-LOCAL

每人一份, 跑在你自己 :30000。它是"你这台机器读写团队 bucket 的代理" + UI + 一个验证工人。它不需要架在中心服务器上, 因为中心是 bucket, 不是它。

你的 Hermes

DOES THE WORK

干活的 Agent。它自己发现技能、自己决定用不用。teamEvolver 不代理它的模型、不注入它的上下文。feed / sync 两个钩子把它和本地 teamEvolver 串起来。

evolve_server

DISTILLS · EXTERNAL SERVICE

真正把一堆会话揉成候选 SKILL.md 的大脑。本 repo 不包含, 外挂经 evolve.server_url 配置。收到 teamEvolver 的空 POST 敲门后, 它自己回头去 bucket 读。数据从不经这条 HTTP。它也用同一把 team AK 读写 bucket, 不是"另一个中心"。

TRUTHS

三件事

"共享"不是服务共享,
是存储共享。

下面三个真相, 逐条纠误。

"要有一台大家共用的 teamEvolver 服务器。"

teamEvolver 每人一份, 跑本地。共享的是 OpenViking bucket; 同一把 team AK 就是团队身份。

session_store.py:108-115 key = sessions/{sid}.json // bucket 层 team-scope hub.py:208-216 comment: "sessions deliberately NOT partitioned per peer: team-level evolution must see everyone." // = bucket 汇合, 服务不共享

"teamEvolver 会自己把会话提炼成技能。"

提炼在外部 evolve_server, 本 repo 不含它的代码。teamEvolver 只做敲门: 会话落 bucket 后, 空 POST 一次 /trigger 通知外部大脑"有新东西了"。数据不经这条 HTTP; evolve_server 自己回头去 bucket 读。控制面走网络, 数据面走存储。

// teamEvolver 侧的完整动作: // 1. session 落 sessions/{sid}.json // 2. 15s 去抖窗口开始 // 3. window 内多次 ingest → // 合并成一次通知 // 4. POST {evolve_url}/trigger // body: 空 · headers: 无 // // evolve_server 收到后: // → 自己去 bucket 读 sessions/* // → 提炼 / 聚类 / 生成候选 // → 候选写回 bucket // // 意义: /trigger 不通只影响 // "发现延迟", 不影响数据汇合

"验证通过后会自动发布到货架。"

没有一条路径把 True Replay 结果连到 push_skills。发布只能人按。

store.py:126-134 save_result() writes verdict // but NEVER calls push_skills grep save_decision → 0 callers skills_admin.py:222-292 push routes gated by _require_admin_request()

SETUP

配置解剖

环境不是清单, 是咒语,
每一行召唤一个物件。

按顺序走完 8 步, 把这张路线单从"图上"召唤到"你机器上"。
左边是你敲的字, 右边是它在物理上让什么开始存在或工作。

conda create -n teamEvolver python=3.11 ↓ 在物理上等于

隔离运行时诞生。teamEvolver 从此和系统 Python 分家, 装什么依赖都进这个笼子里, 不弄脏 Hermes 用的解释器。

pip install -e ".[sharing,validation]" ↓ 在物理上等于

两个能力被装上: sharing 让本地 teamEvolver 会说 OpenViking 协议 (读写 bucket); validation 让它以后能派生 ValidationWorker 起沙盒 A/B。现在只是把 器官 装进身体, 器官还没启用。

~/.teamEvolver/config.yaml · viking_team_api_key ↓ 在物理上等于

团队身份被授予。这把 team AK 是唯一凭据, 决定你能读写哪个 bucket 命名空间。所有 peer 拿同一把 AK, 才算"在同一个团队"; 换了 AK 就换了世界。teamEvolver 服务本身不需要中心部署; AK 就是团队。

teamEvolver start ↓ 在物理上等于

本地代理开机: :30000 起 FastAPI 服务, 后台起 skill 轮询协程 (默认 30s 拉一次 bucket manifest), 后台起 evolve 通知去抖器 (15s 窗口)。如果 validation.enabled=true, 再派生一个 ValidationWorker 常驻协程, 但它现在还睡着 (等 idle)。

~/.hermes/config.yaml · hooks.pre_llm_call ↓ 在物理上等于

入场通道接通。Hermes 每次要调 LLM 之前, 会先跑一次 sync_skills.py; 它去 bucket 拉最新技能清单, 落到 Hermes 的 skills/external_dirs。你 Hermes 从此"每次开口前先翻新笔记"。

~/.hermes/config.yaml · hooks.on_session_end ↓ 在物理上等于

回流通道接通。Hermes 会话一结束, push_session.py 把整段轨迹 POST 给本地 :30000/ingest_session。teamEvolver 内部先跑一次价值判断(判它"有营养"才留), 通过就落到 bucket 的 sessions/{sid}.json。同 sid 后写盖前写。

~/.teamEvolver/config.yaml · evolve.server_url ↓ 在物理上等于

敲门声被登记。以后每次落新会话, 本地 teamEvolver 会在 15s 去抖后空 POST 一次 {url}/trigger。只是敲门, 不带数据。evolve_server 收到敲门自己回头去 bucket 读, 数据从不经这条 HTTP。不接也不影响数据流, 只影响"什么时候被发现"。

~/.teamEvolver/config.yaml · validation.enabled ↓ 在物理上等于

报名参加矿工池。这个开关一开, 步 04 派生的那个 sleeping worker 就开始每 60s 轮询共享 validation/ 队列, 客户端空闲 5 分钟后领 job, 起真沙盒 Hermes 跑 A/B, 结果写回 bucket。每天上限 5 单。关着就纯当消费者, 开了就同时是贡献者。
