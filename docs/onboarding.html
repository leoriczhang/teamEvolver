AGENT / TEAMEVOLVER / OPENVIKING

从真实 Evidence 到可复用的团队能力

teamEvolver 是 Agent 团队能力进化控制面。Agent 执行任务并提交 Session；teamEvolver 管理 Evidence、Skill Candidate、True Replay 和 Candidate Review。OpenViking 保存来源与资产，并提供文档 Compile。

Agent

使用租户 Key 和声明的 user_id 提交 Session、读取 Context、拉取 Skill。真实任务和工具执行由 Agent Runtime 完成。

teamEvolver

提供主服务与控制台，管理进化、人工复核、版本、权限和审计。Skill 变更统一经过 SkillMutationService。

OpenViking

存储来源和授权资产，运行 Compile。Skill 挖掘的模型及执行环境由 OpenViking 配置。

启动与接入

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[all]"
teamEvolver start --daemon
teamEvolver status

打开 http://127.0.0.1:52010/，初始化管理员，配置 OpenViking 和用户权限。Agent 的具体请求契约见 Agent Protocol v2 与 自定义接入。

通道契约
Session 回流POST /ingest_session，使用 agent-session.v2。
Skill 拉取GET /sync/skills?user_id=...，保留完整 Bundle、版本及 tombstone。
Context按租户主体读取获准的 Skill、Memory 和来源引用。
True Replay配置 ReplayAdapterFactory，在独立真实会话中比较 Baseline 与 Candidate。

文档到 Skill Candidate

  1. 注册知识源。 上传或选择可访问的来源目录，标记 Skill 用途。知识库编译使用 Knowledge 用途。
  2. 创建挖掘任务。 选择 1–5 轮、人工补证和每轮运行期限。任务开始时冻结原始来源。
  3. 执行本轮 Compile。 生成 Evidence 映射、缺口、复核问题，以及 Skill、评估说明和统一 Test Dataset。
  4. 复核并补充 Evidence。 回答问题、提交来源引用及附件。下一轮使用原始冻结来源和累计补证，上一轮候选只作为修订上下文。
  5. 完成并提交候选。 查看和编辑最终产物，提交到 True Replay 与 Candidate Review。挖掘完成不会自动 Publish。

七个必需文件分别是 analysis/evidence-map.md、analysis/gaps.md、analysis/review.json，以及 compiled_skill/<name>/ 下的 SKILL.md、EVALUATION.md、BENCHMARK.md 和 benchmark.json。

服务重启恢复任务状态；每轮输入、编译器、请求和产物单独归档。未解决的问题和来源处理警告保留在产物质量中。等待人工复核不占执行并发名额。

知识库编译

知识库页面支持文档上传与转换、目录管理、Wiki 编译、文件编辑、增量编译和关系图。Wiki 与 Skill Candidate 分别治理；知识库编译不会自动发布团队 Skill。
