本版固定以下选择，实施时不需要重新询问这些常规事项：

- 将全部记录视为优秀案例，模型默认只读取对话与课程、章节、知识点、场景信息。
- 数据交换使用 UTF-8 JSONL，每行一条完整案例；OV 执行输入使用每案例一份 Markdown。
- 切分不拆开单条案例。批次同时受案例数、Unicode 字符数和 UTF-8 字节数限制。
- 当前主体 Skill 为 [taikang-dialogue-dimensions-v2](../../../../team_miner/skill_miner/compiler_skills/dialogue-dimensions-v1/SKILL.md)，源码目录保留原路径。用户在原有编译指令界面保存完整正文，运行使用保存的 Skill；无新增任务类型按钮、后端强制替换或冻结附件。
- 仅显式 `groups` 生成维度，单一成员也可形成能力维度。`kept_separate` 与 `deferred` 保留具体方法、来源和原因，交付到 `issues/merge-*.jsonl`，不自动上卷为维度。
- 候选评分口径沿用维度 `notes`，支持 N/A、NE 和暂定 0—3 档；允许 `rubric_pending`，不增加评分字段或硬性校准门禁。
- 默认保留句级定位，默认不输出原文 `quote`。选择输出引文时，逐字一致的要求不可放松。
- 小问题告警或补偿；无法恢复的单条问题局部隔离；数据丢失、越界和无法解析等大问题阻断对应执行单元。
- 多个独立 Compile 完成一项业务任务，进度写 PostgreSQL，知识制品和回执写 OV；OV 本身不改动。
- S0 交付分片维度、案例发现、覆盖记录、问题与验收报告，不创建或发布团队 Skill Candidate。

本次文档已核对当前 `chenzhicong_conv_analy` 分支及本机 OpenViking 源码。先前泰康 S2 的实现、参数与运行结果不作为当前分支已经具备这些能力的证明。
